# Design context — DataHacks UCSD ground-motion timeline

## Design Context

### Users

Hackathon participants, judges, and visitors exploring a UCSD DataHacks project: they want a **single-screen, playable demo** that proves the earthquake PGV dataset directly drives what they see and feel. Context: short attention, laptop screens, often dim rooms.

### Brand Personality

**Focused · empirical · restrained** — the UI should feel like a precision instrument panel, not a game trailer. Confidence comes from clarity and legible numbers, not decoration.

### Aesthetic Direction

- **Theme:** Dark interface (reduces glare, matches “lab / simulation” focus).
- **Visual tone:** Minimal chrome, strong typographic hierarchy, OKLCH neutrals tinted toward a cool blue-teal so surfaces feel cohesive without neon accents.
- **Typography:** **Manrope** for UI and headings (geometric but not generic Inter-adjacent monoculture); **Literata** for supporting copy — editorial serif for “research artifact” contrast.
- **Anti-patterns avoided:** No gradient text, no thick left-edge “alert” stripes, no purple–cyan hero gradients, no stock dashboard card grids for the HUD.

### Design Principles

1. **Data first** — labels state plainly that the timeline is **scenario index** (dataset order), not wall-clock time.
2. **One focal surface** — the canvas is the hero; HUD is peripheral and low-contrast except for key metrics.
3. **Restrained accent** — a single cool accent (OKLCH teal) for the one number that matters most (PGV at the car).
4. **Motion belongs in the 3D view** — the overlay stays stable; shaking is for the simulation, not the UI.

### References

- Dataset: Zenodo “Instantaneous physics-based ground motion maps” (LOH HDF5), local copy under `8170242/`.
